# TEKINO — Digital Products E-Commerce System

## 1. Project Overview

TEKINO is an academic software engineering project focused on an e-commerce system for digital products, including smartphones, laptops, tablets, headphones, smartwatches, and accessories.

The system is intended to help customers discover products, search and filter available items, view product details, manage a shopping cart, place orders, and track purchases. Administrators will be able to manage products, inventory, and customer orders.

This project follows an Agile development approach and focuses on requirements engineering, user stories, product backlog management, and UML modeling.

## 2. Product Vision

To provide customers with a simple, reliable, and user-friendly online platform for discovering and purchasing digital products.

## 3. Project Objectives

- Identify the stakeholders and their needs.
- Define functional and non-functional requirements.
- Write user stories and establish acceptance criteria.
- Create and prioritize the product backlog.
- Plan development iterations using an Agile approach.
- Model system behavior using UML use case and activity diagrams.
- Maintain project documentation and track changes using GitHub.

## 4. Project Scope

### In Scope

- User registration and login
- Product browsing, searching, and filtering
- Viewing product details
- Shopping cart management
- Checkout and order placement
- Online payment interaction
- Order tracking
- Product, inventory, and order management for administrators

### Out of Scope for the Initial Version

- Native Android and iOS applications
- Managing the delivery company's internal operations
- A multi-vendor marketplace

## 5. Agile Development Approach

The project uses an iterative and incremental Agile approach.

Work items will be documented and prioritized in a Product Backlog. Selected items will be planned for individual Sprints. Each Sprint will involve the relevant analysis, design, implementation, and testing activities, followed by a review of the results and refinement of the backlog based on feedback.

The project documentation will evolve as requirements become clearer.

## 6. Planned Deliverables

- Stakeholder identification
- Functional requirements

- Five user stories with acceptance criteria
- Prioritized product backlog
